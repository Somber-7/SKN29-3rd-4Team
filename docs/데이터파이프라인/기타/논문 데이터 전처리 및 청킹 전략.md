# 논문 데이터 전처리 및 청킹(Chunking) 최적화 전략 (정확도 최우선)

처리 속도보다는 데이터 추출의 정확도와 검색 성능(Quality)을 최우선으로 하여, 추가된 논문 3건에 대한 전처리 및 청킹 파이프라인을 구축합니다.

## 1. 텍스트 추출 도구의 최적화 (정확도 최우선)
- **OCR 배제 및 Text Parser 도입**: 대상 논문들은 이미지 스캔본이 아닌 텍스트 레이어가 존재하는 디지털 PDF입니다. 
- **정밀 추출**: 처리 속도는 다소 느려지더라도 무방하므로, 글자 누락이나 순서 뒤틀림 없이 가장 정밀하게 텍스트와 레이아웃을 추출할 수 있도록 `pdfplumber`를 사용합니다.

## 2. 논문 도메인에 맞춘 청킹(Chunking) 규칙
- **1차 분리**: 빈 줄(연속된 개행 `\n\n`)을 기준으로 문서를 단락 단위로 분리하고, 단락 내부의 단순 줄바꿈은 공백으로 치환해 문맥을 잇습니다.
- **짧은 단락 병합 (50자 미만)**: 목차, 소제목 등 50자 미만의 단락은 독립적인 의미가 적으므로, 문맥 단절을 막기 위해 **반드시 다음 단락(본문)의 시작 부분에 병합**합니다.
- **긴 단락 분할 (500자 초과)**: 정보 밀도가 높은 500자 초과 단락은 정규표현식(`(?<=[.?!])\s+`)을 사용하여 문장 종결 기호를 기준으로 안전하게 하위 분할합니다.

## 3. 메타데이터(Metadata) 체계 구축
각 청크(단락)별로 아래 **5가지 필수 메타데이터**를 추출 및 매핑하여, 추후 ChromaDB 검색 필터링과 LLM의 출처 인용에 활용합니다.
- `title`: 논문명
- `author`: 저자명
- `year`: 발행 연도
- `source`: PDF 파일명
- **`page_number`**: 출처 페이지 번호 (새로 추가됨)

## 4. 띄어쓰기 손실 복원 및 한자(Hanja) 예외 처리 전략
- **임계치 기반 교정**: 추출된 텍스트의 전체 길이 대비 공백(Space) 비율이 5% 미만인 논문에 대해서만 선별적으로 `pykospacing` (또는 `KoNLPy` 기반)의 교정 로직을 가동합니다.
- **한자(Hanja) 보존 및 에러 방지**: 명명학/음운론 논문 도메인 특성상 한자가 다수 혼용되어 있습니다(예: 音節, 特性 등). 띄어쓰기 모델이 연속된 한자를 인식하지 못해 오작동하거나 텍스트를 훼손하는 것을 막아야 합니다.
- **강력한 예외 처리 로직**: 교정 모듈 가동 전 정규표현식을 이용해 **한자 블록을 식별하여 임시 토큰으로 치환(보호)한 뒤**, 띄어쓰기 복원이 끝난 후 원래의 한자 블록으로 **원복**하는 로직을 스크립트에 반드시 포함합니다. 이를 통해 한자가 포함된 문장도 원형 훼손 없이 안전하게 띄어쓰기가 복원되도록 보장합니다.
