# GPT-4o-mini 파인튜닝 방향성 및 계획서

> **문서 목적**: SKN29-3rd-4Team 프로젝트의 8단계 목표인 `gpt-4o-mini` 모델의 파인튜닝(Fine-Tuning)을 성공적으로 수행하기 위한 구체적인 방향성과 단계별 실행 계획 정의.
> **기반 자료**: 사용자 제공 가이드(Phase 1~4), 프로젝트 `README.md`, 기존 `sLLM_파인튜닝_전략.md`

---

## 1. 파인튜닝 방향성 (Direction)

프로젝트 아키텍처(LangGraph) 내에서 LLM은 크게 **의도 분류(Router)**와 **최종 답변 생성(Generator)**의 두 가지 역할을 수행합니다. 파인튜닝의 핵심 방향은 **"프롬프트 다이어트"**와 **"출력 포맷/어투의 완벽한 내재화"**입니다.

### 1-1. 모델 역할별 튜닝 타겟
현재 LangGraph 구조를 고려할 때, 최우선 타겟은 **최종 답변 생성(Generator) 모델**입니다.
*   **Generator 튜닝 (우선순위 1)**: 복잡한 작명 조건(오행, 수리, 한자 뜻), 출처 태그(`[한자: 木오행]`, `[논문: 2024 트렌드]`), 그리고 필수 안내문(면책 고지)을 프롬프트 지시 없이도 일관성 있게 출력하도록 학습.
*   **Router 튜닝 (우선순위 2)**: 사용자의 복합 질의(ex. "김씨 남자이름 오행 맞춰서 지어줘")를 받아 `external_api`, `internal_rag`, `graph_db` 등의 도구를 정확하게 매핑하는 JSON 포맷 출력 강제.

### 1-2. 파인튜닝 기대 효과
*   **비용 및 지연시간 감소**: 시스템 프롬프트에 나열된 수많은 "금지 사항", "출력 형식 예시"를 제거하여 토큰 사용량을 대폭 절감하고 응답 속도 향상.
*   **답변 품질의 일관성**: 전문적이고 따뜻한 "작명가" 어투를 고정하고, `[출처: law_col]`와 같은 출처 라벨링의 누락을 방지.
*   **예외 상황(Edge Case) 방어력 상승**: 정보 부족(성씨 누락), 악의적 질문, 도메인 외 질문에 대해 당황하지 않고 정해진 규칙(ex. clarification 요청)대로 대응.

## 2. 단계별 실행 계획 (Plan)

### Phase 1: 고품질 학습 데이터셋(Dataset) 설계 (데이터 50~100건)

양보다 **질(Quality)**이 중요합니다. 기존 `sLLM_파인튜닝_전략.md`에서 기획한 CoT(Chain of Thought) QA 방식을 계승하여 데이터셋을 구성합니다.

*   **데이터 소스 매핑 (Context 확보)**
    *   `src/data/processed/hanja_documents.json`: 한자 획수, 오행 근거
    *   `db_server`의 계산 결과: 81수리 및 오행 길흉 데이터
    *   테스트 과정에서 정상적으로 출력되었던 양질의 기존 답변 (Log 재활용)
*   **데이터 배분 (총 100건 목표)**
    *   작명 추천 (조건 충족 형태): 60건
    *   오행 및 81수리 단순 풀이: 15건
    *   법령/인명용 한자 관련 질의: 10건
    *   **Edge Case (정보 누락, 비매너 질의 등): 15건** (매우 중요)

### Phase 2: GPT-4o를 활용한 합성 데이터(Synthetic Data) 자동 생성

수작업을 최소화하기 위해 파이썬 자동화 스크립트(`src/preprocess/generate_synthetic_qa.py` - 신규 작성 예정)를 구축합니다.

1.  **스크립트 로직**:
    *   준비된 원본 Context(예: 한자 뜻풀이, 수리 길흉 텍스트)를 `gpt-4o` 모델에 입력.
    *   프롬프트를 통해 "가상의 사용자 질문"과 "완벽한 포맷(출처, 면책 고지 포함)의 어시스턴트 답변" 쌍을 생성하도록 지시.
2.  **데이터 규격 (`.jsonl`)**:
    ```json
    {"messages": [{"role": "system", "content": "당신은 전문적이고 따뜻한 어투를 사용하는 작명가 AI입니다."}, {"role": "user", "content": "최씨 여자아이 이름 지어줘. 수리 4격이 좋았으면 해. (수집된 정보: ...)"}, {"role": "assistant", "content": "최씨 성을 가진 공주님의 이름을 고민 중이시군요. ...\n\n* **성씨 정보**: ...\n* **수리 4격**: ...\n\n⚠️ 면책 고지: 본 시스템은 참고용이며..."}]}
    ```
3.  **데이터 분리**: 생성된 JSONL 파일을 8:2 (학습용 `train.jsonl`, 검증용 `valid.jsonl`)로 분리.

### Phase 3: OpenAI API를 통한 파인튜닝 실행

자동화 스크립트를 통해 `gpt-4o-mini-2024-07-18` 모델의 파인튜닝을 실행합니다. (`src/data/run_finetuning.py` - 신규 작성 예정)

1.  **파일 업로드**: `client.files.create()`를 사용하여 `train.jsonl` 및 `valid.jsonl` 업로드.
2.  **Job 생성**: 
    *   `model="gpt-4o-mini-2024-07-18"`
    *   `hyperparameters={"n_epochs": 3}` (기본값 3, 과적합 시 조정)
3.  **모니터링**: 대시보드 및 스크립트를 통해 Loss 그래프 확인. Validation Loss가 튀지 않고 안정적으로 우하향하는지 검토.

### Phase 4: LangGraph 파이프라인 이식 및 최적화

파인튜닝 완료 후 생성된 커스텀 모델(`ft:gpt-4o-mini-2024-07-18:my-org:custom-name`)을 시스템에 적용합니다.

1.  **모델 ID 교체**: `src/graph/naming_graph.py` 내의 Generator LLM 호출 부에 새 모델 ID 적용.
2.  **프롬프트 다이어트**: 기존 System Prompt에 길게 나열되어 있던 "출력 형식 예시", "반드시 출처를 [ ] 안에 넣을 것", "면책 고지 필수" 등의 지시문을 과감히 삭제하거나 한 줄로 축약.
3.  **Temperature 재설정**: 포맷이 모델 자체에 내재화되었으므로, `temperature`를 기존 `0.0~0.1` 수준에서 `0.4~0.6`으로 약간 상향 조정하여 이름 추천의 다양성(Creativity) 확보.
4.  **최종 평가 (README 9단계 진행)**: 
    *   Ground Truth QA 30~50개를 대상으로 LM-as-a-Judge 평가 수행.
    *   출처 태그 준수율, 할루시네이션, 답변의 전문성/어투 검증.
