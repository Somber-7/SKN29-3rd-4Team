# 데이터 수집 및 전처리 문서

## 현행 구현 기준 보완 (2026-06-16)

> 문서 상태: 전체 데이터 전처리 요약 문서. 아래 표는 실제 raw/processed/Chroma 산출물을 기준으로 갱신한 현재 기준이다.

본 문서는 Pipeline Server가 사용하는 데이터 산출물의 통합 기준표로 활용한다. Open WebUI에서 들어온 질문은 Pipeline 내부 LangGraph를 거쳐 ChromaDB, `db_server.py`, `law_server.py`, `graph_server.py` 등으로 분기되므로, 각 데이터의 원본, 정제 산출물, 운영 사용처를 일관되게 관리해야 한다.

| 데이터 | 원본/입력 | 정제 산출물 | Chroma/사용처 | 현재 기준 |
|---|---|---|---|---|
| 인명용 한자 | `peoplehanja.json`, 오행 XLSX, Unihan TXT | `hanja_documents.json` | `hanja_col`, Graph MCP | 운영 문서 2,420건, Chroma 전체 2,438건 |
| 확장 한자 후보 | 운영 한자 외 추가 후보 | `hanja2_candidate_documents.json` | 운영 DB 직접 투입 아님 | 6,564건 |
| 81수리 | `81suri.json` | `suri_documents.json` | `suri_col`, `db_server.py` | 81건 |
| 오행 조합 | `yinyang.json` | `ohaeng_documents.json` | `ohaeng_col`, `db_server.py` | 125건 |
| 법령 | 법률/규칙 PDF | `law_articles.json` | `law_col` | processed 250건, Chroma 248건 |
| 순우리말 이름 | 크롤링/정제 데이터 | `urimalsam_names.json` | `urimalsam_col` | 301건 |
| 논문 | 작명 관련 논문 PDF 3건 | `paper_documents.json` | `paper_col` | 264건. text 216, table 48 |
| 성씨 오행 | 한자/성씨 보조 데이터 | `surname_ohaeng.json` | `naming_graph.py` fallback | 258개 |
| OCR 시도 | `정겨운우리말.pdf` | `ocr_raw_full.txt`, `ocr_structured.txt`, `ocr_clean_log.txt` | 참고/보존 | 운영 RAG와 직접 연결은 제한적 |

현재 기준에서 `hanja_col` 2,438건은 Chroma 컬렉션 전체 count이고, 자동 작명 추천에 사용하는 인명 한자 풀은 `is_person_name_hanja=True`인 2,420건이다. 순우리말 운영 데이터는 301건, 성씨 fallback 데이터는 258개를 기준으로 관리한다.

## 3. 컬렉션별 상세

### 3-1. suri_col — 81수리 운세 (81건)

**원본:** `data/raw/reference/81suri.json`  
**출처:** https://github.com/forteleaf/makename/tree/master/data

**전처리 (`process_suri.py`):**
- 수리 번호(1~81)별 운세 텍스트를 Document로 변환
- 메타데이터: `suri_number`, `rating(吉/凶/半吉)`, `short_desc`

**청킹 전략:** 수리 번호 1개 = 문서 1건 (Fixed-size: 수리 단위 분할)

**임베딩:** `jhgan/ko-sroberta-multitask`

---

### 3-2. ohaeng_col — 오행 조합 운세 (125건)

**원본:** `data/raw/reference/yinyang.json`  
**출처:** https://github.com/forteleaf/makename/tree/master/data

**전처리 (`process_suri.py`):**
- 오행 3요소 조합(성씨·이름1·이름2)별 운세 텍스트를 Document로 변환
- 메타데이터: `pair1`, `pair2`, `pair1_relation`, `pair2_relation`, `overall_rating`

**청킹 전략:** 오행 조합 1가지 = 문서 1건 (Fixed-size: 조합 단위 분할)

**임베딩:** `jhgan/ko-sroberta-multitask`

---

### 3-3. hanja_col — 인명용 한자 (2,438건)

**원본:** 법제처 인명용 한자 고시 데이터

**전처리 (`index_hanja_chroma.py`):**
- 한자별 뜻·음·획수·오행 정보를 정형화
- `is_person_name_hanja=True` 플래그로 인명 허용 여부 구분
- 필수 필드 검증: `hangul`, `hanja`, `strokes`, `resource_ohaeng`

**메타데이터 스키마:**

| 필드 | 타입 | 설명 |
|---|---|---|
| `hanja` | str | 한자 문자 |
| `hangul` | str | 이름 발음 |
| `sound_meaning` | str | 뜻 |
| `strokes` | int | 획수 |
| `resource_ohaeng` | str | 자원오행 (목/화/토/금/수) |
| `is_person_name_hanja` | bool | 인명 사용 허용 여부 |

**청킹 전략:** 한자 1자 = 문서 1건 (Fixed-size: 글자 단위)

**임베딩:** `jhgan/ko-sroberta-multitask`

---

### 3-4. law_col — 법령 조문 (248건)

**원본:** 가족관계등록법·인명용 한자 관련 PDF (`data/raw/pdf/`)

**전처리 (`preprocess_law.py`):**
1. `pypdf`로 PDF 텍스트 추출
2. 법제처 페이지 헤더/푸터 제거 (정규표현식)
3. **조항(Article) 단위 분할** — `제N조` 패턴으로 분리
4. `KoNLPy Okt` 형태소 분석 → 불용어 제거 → 텍스트 정규화
5. `data/processed/law_articles.json`으로 저장

**청킹 전략:** 조항(제N조) 단위 분할 (Recursive/Semantic — 법령 구조 기반)

**형태소 분석 적용:**
- `KoNLPy Okt` 사용
- 불용어: 조사·어미·접속사 제거 (`이/가/은/는/을/를/에/의/로` 등)
- 목적: 법령 특수 용어의 검색 정확도 향상

**임베딩:** `jhgan/ko-sroberta-multitask`

---

### 3-5. urimalsam_col — 순우리말 이름 (301건)

**원본:** https://baby-name.kr/ 웹 크롤링 (`crawl_urimalsam.py`)

**전처리 (`index_urimalsam.py`):**
- 이름·뜻·성별 적합성 메타데이터 구조화
- 성별 태그: `"여자에게"`, `"남자에게"`, `"남녀 모두에게"` — 추천 시 필터링에 활용

**메타데이터 스키마:**

| 필드 | 타입 | 설명 |
|---|---|---|
| `name` | str | 순우리말 이름 단어 |
| `meaning` | str | 뜻풀이 |
| `gender` | str | 성별 적합성 태그 |

**청킹 전략:** 이름 단어 1건 = 문서 1건 (Fixed-size: 단어 단위)

**임베딩:** `jhgan/ko-sroberta-multitask`

**추가 처리:** 랜덤 샘플링 기반 검색 (`sample_urimalsam`) — 매 요청마다 다양성 확보

---

### 3-6. paper_col — 학술 논문 (264건)

**원본:** 작명 관련 국내 학술 논문 PDF (KCI 등재 논문)

**출처:**
- https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003281155
- https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003041839
- https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003171554

**전처리 (`ocr_extract.py`, `ocr_clean.py`, `index_papers.py`):**
1. PDF OCR 추출 (`ocr_extract.py`)
2. OCR 노이즈 제거, 표/본문 구분 (`ocr_clean.py`)
3. **Semantic Chunking** — 본문(text)과 통계표(table)를 별도 청크로 분리
   - `chunk_type: "text"` — 논문 본문 단락
   - `chunk_type: "table"` — 이름 통계·빈도 데이터 테이블

**특이사항:** 수동 임베딩으로 인덱싱 (ChromaDB EF 없이 raw vector 직접 삽입)  
→ 검색 시 `get_collection(name="paper_col")` (embedding_function 인자 없음)

**임베딩:** `jhgan/ko-sroberta-multitask` (SentenceTransformer 직접 호출)

## 5. Graph DB 데이터 구조 (Neo4j)

**노드 유형:**

| 노드 | 속성 | 설명 |
|---|---|---|
| `Hanja` | hanja, hangul, strokes, meaning | 인명용 한자 |
| `Sound` | value | 발음 (한글 음절) |
| `Stroke` | value | 획수 |
| `Ohaeng` | name | 오행 (목/화/토/금/수) |
| `Law` | name | 관련 법령 |

**관계 유형:**

| 관계 | 방향 | 의미 |
|---|---|---|
| `HAS_SOUND` | Hanja → Sound | 발음 연결 |
| `HAS_STROKES` | Hanja → Stroke | 획수 연결 |
| `BELONGS_TO` | Hanja → Ohaeng | 자원오행 분류 |
| `PERMITTED_BY` | Hanja → Law | 인명용 허용 근거 법령 |
| `GENERATES` | Ohaeng → Ohaeng | 상생 관계 |
| `CONTROLS` | Ohaeng → Ohaeng | 상극 관계 |
