# 한자 확장 후보군 Document/Metadata 변환 작업 기록

**작성일**: 2026-06-15  
**최종 정리일**: 2026-06-16  
**작업 범위**: `hanja_documents.json`에 적재되지 않은 한자 6,564건을 별도 후보군 JSON으로 정리하고 검증  
**기준 메인 파일**: `data/processed/hanja_documents.json`  
**최종 후보군 파일**: `data/processed/hanja2_candidate_documents.json`

## 1. 작업 목적

기존 메인 한자 데이터인 `hanja_documents.json` 2,420건은 ChromaDB, Neo4j, 작명 파이프라인의 기준 데이터로 유지한다.

이번 작업의 목적은 `hanja.pdf` 원본 범위에서 메인 데이터에 적재되지 않은 한자를 기존 데이터의 대체본으로 만들지 않고, 별도 후보군 데이터로 분리해 관리하는 것이다.

따라서 `hanja2_candidate_documents.json`은 확정 메인 데이터가 아니라, 한자 확장 후보군을 검색, 검토, 후속 보강에 사용할 수 있도록 정리한 보조 JSON이다.

## 2. 최종 보존 파일

최종 보존 파일은 다음 2개로 제한한다.

| 구분 | 경로 | 설명 |
| --- | --- | --- |
| 후보군 JSON | `data/processed/hanja2_candidate_documents.json` | 메인 JSON과 같은 document/metadata 구조를 가진 후보군 데이터 |
| 작업 문서 | `docs/한자_확장_후보군_문서_메타데이터_변환.md` | 후보군 생성 목적, 구조, 정리 기준, 검증 결과 기록 |

중간 검증 JSON, OCR raw 파일, PDF 렌더링 이미지, 임시 교차검증 보고서는 최종 보존 대상에서 제외한다. 필요한 검증 수치는 이 문서에 요약 기록한다.

## 4. 후보군 JSON 구조

`hanja2_candidate_documents.json`의 각 항목은 메인 JSON과 동일하게 다음 3개 최상위 필드를 가진다.

```json
{
  "id": "hanja_OHE2-00001",
  "document": "한자 仮(가)는 뜻 검증이 필요한 인명용 한자 확장 후보이다. 유니코드는 U+4EEE, 획수는 6획, 발음오행은 목, 자원오행 후보는 화이다.",
  "metadata": {
    "type": "hanja",
    "collection": "hanja_profiles",
    "source": "hanja2_candidate_graph_ready.json",
    "profile_id": "OHE2-00001",
    "hangul": "가",
    "hanja": "仮",
    "unicode": "U+4EEE",
    "sound_meaning": "뜻 검증대기",
    "strokes": 6,
    "sound_ohaeng": "목",
    "resource_ohaeng": "화",
    "is_person_name_hanja": true
  }
}
```

metadata는 메인 `hanja_documents.json`과 같은 12개 필드만 유지한다.

## 5. 처리 과정

1. 기존 메인 파일 `hanja_documents.json`은 수정하지 않았다.
2. 후보군 JSON은 메인 JSON과 같은 `id`, `document`, `metadata` 구조로 정리했다.
3. 후보군 metadata는 메인 JSON과 같은 12개 필드만 남겼다.
4. 검증용 confidence, audit, CSV, validation/report 파일은 최종 보존 대상에서 제외했다.
5. `document` 문장에는 확정 데이터처럼 보이지 않도록 `인명용 한자 확장 후보`, `자원오행 후보`, `뜻 검증이 필요한` 표현을 사용했다.
6. 기존 ChromaDB, Neo4j, MCP server 관련 코드는 수정하지 않았다.
7. 최종 보존 대상은 `hanja2_candidate_documents.json`과 이 문서 2개로 정리했다.

## 8. PDF OCR 교차검증 요약

`hanja.pdf`는 뜻, 획수, 발음오행, 자원오행을 제공하는 사전형 데이터가 아니라 음별 허용 한자 목록이다. 따라서 이 PDF는 `sound_meaning`을 채우는 근거로 사용할 수 없고, `(hangul, hanja)`가 원본 PDF의 해당 음 아래에 존재하는지 확인하는 보조 검증에만 사용할 수 있다.

검증 과정에서 임시로 다음 산출물을 만들었다.

| 임시 산출물 | 역할 |
| --- | --- |
| `hanja_pdf_ocr_raw.json` / `hanja_pdf_ocr_raw.txt` | PDF 54페이지 Windows OCR raw 결과 |
| `hanja_pdf_ocr_reference_rows.json` | OCR 좌표 기반 행/열 정규화 결과 |
| `hanja_pdf_verification_documents.json` | 후보 검증용 document/metadata 구조 기준표 |
| `hanja2_candidate_pdf_document_crosscheck.json` | 후보군 JSON과 PDF 검증용 기준표의 교차검증 보고서 |

위 파일들은 최종 보존 대상이 아니며, 핵심 결과만 아래에 기록한다.

| 항목 | 결과 |
| --- | --- |
| OCR 대상 PDF 페이지 수 | 54 |
| OCR raw 빈 페이지 | 0 |
| OCR 기반 검증용 문서 수 | 6,586 |
| 후보군 6,564건 중 PDF OCR exact match | 1,890 |
| 뜻 검증대기 3,605건 중 PDF OCR exact match | 908 |
| 뜻 검증대기 exact match 중 OCR high | 895 |
| 뜻 검증대기 exact match 중 OCR medium | 13 |

PDF OCR exact match는 “원본 PDF에서 같은 음-한자 조합이 확인됨”을 의미한다. 그러나 `hanja.pdf`에는 뜻/획수/오행 정보가 없으므로, 이 결과만으로 `뜻 검증대기`를 해소하지 않는다.

## 9. 다중독음 및 잔여 리스크

후보군에는 같은 한자가 여러 음으로 나뉜 다중독음 그룹이 존재한다.

| 항목 | 결과 |
| --- | --- |
| 같은 한자 반복 그룹 | 211 |
| 반복 그룹에 포함된 행 수 | 426 |
| 동일 한자 그룹 내 자원오행 충돌 | 14 |
| 동일 한자 그룹 내 획수 충돌 | 55 |

이 값들은 후보군을 확정 데이터로 전환하기 전에 별도 검토가 필요하다. 현재 단계에서는 후보군 상태를 유지한다.

## 11. Git 반영 범위

이번 후보군 정리 작업에서 커밋/푸시 대상으로 남길 파일은 아래 2개뿐이다.

| 구분 | 경로 |
| --- | --- |
| 후보군 JSON | `data/processed/hanja2_candidate_documents.json` |
| 작업 문서 | `docs/한자_확장_후보군_문서_메타데이터_변환.md` |

`data/chroma/*` 변경은 이번 후보군 JSON 정리 범위가 아니며, ChromaDB, Neo4j, MCP server 반영 작업도 이번 단계에서는 진행하지 않는다.

2026-06-16 원격 확인 기준으로 현재 브랜치 `jiyong`, `origin/jiyong`, `origin/main`은 모두 같은 커밋 `00e216c`를 가리키고 있었다. 따라서 이 시점에는 푸시 전에 `origin main`을 먼저 pull 해야 하는 원격 선행 변경은 없었다.

## 12. 후속 사용 방향

`hanja2_candidate_documents.json`은 메인 데이터의 대체본이 아니라 확장 후보군이다.

후속 ChromaDB 또는 Neo4j 적재가 필요할 경우 기존 `hanja_col`이나 메인 그래프를 바로 덮어쓰지 않고, 후보군 전용 컬렉션 또는 후보군 전용 그래프 레이어로 분리하는 방식이 안전하다.

확정 전환 조건은 다음과 같다.

1. `뜻 검증대기` 잔여 항목을 신뢰 가능한 사전형 원천으로 보강한다.
2. 다중독음 그룹의 획수/자원오행 충돌을 검토한다.
3. 최종 검증 후 후보 표현을 확정 표현으로 전환한다.
4. 그 이후에 ChromaDB, Neo4j, MCP server 반영 여부를 별도 작업으로 판단한다.
