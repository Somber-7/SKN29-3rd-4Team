# GPT 파이프라인 vs Qwen 파인튜닝 비교 평가 보고서

> 작성일: 2026-06-17
> 비교 목적: RAG+파이프라인 방식 vs 파인튜닝 방식의 작명 QA 품질 비교

---

## 1. 비교 배경

본 프로젝트는 동일한 작명 도메인에 대해 두 가지 접근법을 비교한다.

| 구분 | GPT 파이프라인 | Qwen 파인튜닝 |
|---|---|---|
| **핵심 아이디어** | 외부 지식을 실시간 검색하여 LLM에 제공 | 도메인 지식을 모델 파라미터에 내재화 |
| **생성 모델** | `gpt-5.4-mini` | `qwen-lora` (Qwen3.5-4B + LoRA v2) |
| **지식 접근 방식** | RAG (ChromaDB, Neo4j, SQLite, 법령 API) | 파인튜닝 (1만 건 작명 데이터) |
| **응답 방식** | 검색된 컨텍스트 기반 생성 | 자연어 질의 직접 처리 |
| **Judge 모델** | `gpt-5.4` | `gpt-5.4` |
| **평가 스크립트** | `tests/rag_eval.py` | `tests/qwen_eval.py` |

---

## 2. 평가 지표 대응

두 방식은 서로 다른 지표 체계를 사용하므로 공통 지표(GR, AR)를 중심으로 비교하되, 방식별 고유 지표도 함께 제시한다.

| 지표 | GPT 파이프라인 | Qwen 파인튜닝 | 비교 가능 여부 |
|---|---|---|---|
| Context Relevance (CR) | RAG 검색 품질 측정 | 해당 없음 (RAG 미사용) | 직접 비교 불가 |
| Factual Accuracy (FA) | 해당 없음 | 파인튜닝 지식 정확성 | 직접 비교 불가 |
| **Groundedness (GR)** | 컨텍스트 근거 여부 | 한자/오행 근거 포함 여부 | **공통 비교 가능** |
| **Answer Relevance (AR)** | 질문 답변 여부 | 질문 답변 여부 | **공통 비교 가능** |

## 6. 방법론 관점에서의 해석

### RAG+파이프라인 방식 (GPT)

**장점:**
- 수치 계산, 관계 탐색, 법령 검색 등 구조화된 지식을 외부 도구로 정확히 처리
- 데이터 업데이트 시 모델 재학습 불필요 — 데이터만 갱신
- 할루시네이션 발생 시 컨텍스트에서 근거를 추적 가능

**단점:**
- 복합 조건 추천 시 여러 도구 결과를 LLM이 연계하지 못해 성능 저하 (케이스 1, 8)
- RAG 인프라(ChromaDB, Neo4j, SQLite) 유지 비용 존재
- 컨텍스트 길이 제한으로 대규모 검색 결과 처리에 제약

### 파인튜닝 방식 (Qwen)

**장점:**
- 추론 시 외부 시스템 의존성 없음 — 독립적 배포 가능
- 이름 추천 출력 형식(## [이름 N])을 파인튜닝으로 일관되게 학습
- 단순 이름 추천 요청에 빠른 응답 (20~40초)

**단점:**
- 수치 계산(수리 4격), 법령 조문 등 정형화된 지식의 정확한 내재화 한계
- 오행 상생/상극 관계 등 규칙 기반 지식에서 일관성 부재
- 복잡한 복합 조건 처리 시 타임아웃 위험

## 7. 결론

| 관점 | 결론 |
|---|---|
| 수치 정확성 | RAG+파이프라인이 압도적으로 우위 (수리 계산 5.00 vs 1.00) |
| 사실 근거성 | RAG+파이프라인 우위 — 컨텍스트 기반 검증 가능 |
| 질문 응답성 | RAG+파이프라인 우위 — 복합 조건 대부분 처리 |
| 형식 일관성 | Qwen이 출력 포맷 학습은 성공적 (파인튜닝 효과 확인) |
| 인프라 복잡도 | Qwen이 단순 (단일 모델 서빙) |

**파인튜닝은 출력 형식 학습에는 효과적이나, 도메인 특화 지식(수리 계산, 오행 원리, 법령 조문)의 정확한 내재화에는 한계가 있다.** 구조화된 지식이 핵심인 작명 도메인에서는 RAG+파이프라인 방식이 신뢰성과 정확성 면에서 우위를 가진다.

향후 개선 방향으로는 파인튜닝 모델과 RAG를 결합하는 **하이브리드 접근(파인튜닝된 모델 + 외부 도구)** 을 고려할 수 있다. 이를 통해 파인튜닝의 형식 일관성과 RAG의 사실 정확성을 동시에 확보할 수 있다.
