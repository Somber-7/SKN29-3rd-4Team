# GPT-4o-mini 파인튜닝 심화 전략 계획서 (최상위 전문가 에디션)

> **문서 목적**: LangGraph 기반 맞춤 작명 QA 시스템의 최종 응답 품질과 사용자 경험(UX)을 극대화하기 위한 GPT-4o-mini 파인튜닝 마스터 플랜. (실무 스크립트 명세 및 포맷 포함)

---

## 1. 파인튜닝 핵심 목표 및 필수 고려 사항

단순히 '말을 예쁘게 하는 것'을 넘어, 시스템의 안정성과 사용자 경험(UX)을 결정짓는 핵심 목표들입니다.

1.  **UX 최적화 및 지연 시간(Latency) 감소 (Prompt Diet)**
    *   시스템 프롬프트의 길이를 대폭 줄여 입력 토큰 처리 시간(TTFT)을 최소화합니다.
    *   모바일/웹 UI에서 가독성이 뛰어난 마크다운(Bullet points, 굵은 글씨, 명확한 단락 구분)을 프롬프트 지시 없이도 자발적으로 출력하도록 만듭니다.
2.  **포맷 강제화 및 RAG 환각(Hallucination) 원천 차단**
    *   어떤 복잡한 문서가 검색되더라도 `## [이름 1]`, `[출처: law_col]`, `⚠️ 면책 고지: ...` 형태의 포맷을 절대 깨뜨리지 않습니다.
    *   **[필수 고려] Context-Aware Suppression**: 만약 RAG 검색 결과에 원하는 정보가 없다면, 억지로 지어내지 않고 *"현재 수집된 데이터(논문/법령)에서는 해당 내용을 찾을 수 없습니다"*라고 **당당하게 모른다고 답하는 훈련**이 반드시 포함되어야 합니다.
3.  **다중 의도(Multi-intent) 및 예외 상황의 매끄러운 방어**
    *   정보가 누락되었거나(예: 성씨 미입력), 도메인을 벗어난 질문이 들어왔을 때, 기계적인 에러 메시지가 아닌 "전문 작명가" 페르소나를 유지하며 부드럽게 재질문(Clarification)을 유도합니다.

---

## 2. 단계별 실행 계획 (통합 파이프라인)

> 💡 **사용자 질문에 대한 답변**: 파인튜닝 시 이 모든 다양한 상황(추천, 법령, 예외상황 등)을 **반드시 하나의 `.jsonl` 파일에 섞어서(Shuffle) 한 번에 학습**시켜야 합니다.

### Phase 1: 실전 UX 기반 통합 데이터셋 설계 및 수집 (100~150건)
팀원들이 직접 **오타, 단답형, 파편화된 진짜 유저 같은 질문(Raw Queries)**을 수동으로 작성합니다.
*   `30%`: 심화 작명 시나리오 (오행/수리 다중 조건 및 충돌)
*   `20%`: 오류 복구 및 대안 제시 (불가능한 요구 시 법령 근거로 대안 제시)
*   `20%`: 정보 누락 및 모호함 해결 (성씨/성별 재질문 유도)
*   `20%`: 평가 및 단일 RAG 질의 (특수 출처 라벨링)
*   `10%`: 아웃 오브 도메인 (OOD, 도메인 이탈 방어)

### Phase 2: GPT-4o 기반 '완벽한 정답(Label)' 생성 자동화 (`generate_synthetic_qa.py`)
1.  **Teacher Model(GPT-4o) 활용**: Phase 1의 거친 질문들을 `gpt-4o`에 넣어 완벽한 포맷의 정답을 뽑아내는 스크립트(`generate_synthetic_qa.py`)를 실행합니다.
2.  **데이터 규격 및 린팅 (HITL 검수)**: 변환된 결과물이 아래의 규격을 정확히 지키는지 마크다운 띄어쓰기 하나까지 사람(HITL)이 교정합니다.
    ```json
    {"messages": [{"role": "system", "content": "당신은 전문적이고 따뜻한 어투를 사용하는 작명가 AI입니다."}, {"role": "user", "content": "최씨 여자아이 이름 지어줘. 수리 4격이 좋았으면 해. (수집된 정보: ...)"}, {"role": "assistant", "content": "최씨 성을 가진 공주님의 이름을 고민 중이시군요. ...\n\n* **성씨 정보**: ...\n* **수리 4격**: ...\n\n⚠️ 면책 고지: 본 시스템은 참고용이며..."}]}
    ```

### Phase 3: RAG Raw-Data Injection 매핑 (매우 중요)
학습 데이터(`.jsonl`)의 `user` 메시지나 `system` 메시지 안에는, 실제 LangGraph가 ChromaDB에서 뽑아온 날것의(Raw) 텍스트 청크 형태가 그대로 들어있어야 합니다.

### Phase 4: OpenAI API 튜닝 실행 (`run_finetuning.py`)
1.  **Job 생성**: 완성된 `.jsonl` 파일을 8:2 (학습용 `train.jsonl`, 검증용 `valid.jsonl`)로 분리하여 OpenAI API(`client.files.create()`, `client.fine_tuning.jobs.create()`)를 통해 업로드하고 학습을 트리거합니다.
2.  **모델 지정**: `model="gpt-4o-mini-2024-07-18"` 사용.

### Phase 5: LangGraph 연동 및 환경 최적화
1.  **모델 ID 교체**: 새로 발급받은 `ft:gpt-4o-mini...` 모델 ID를 `src/graph/naming_graph.py`의 Generator 노드에 갈아 끼웁니다.
2.  **시스템 프롬프트 압축**: 기존 프롬프트의 지시문을 1~2줄로 대폭 축소합니다.
3.  **Temperature 상향**: 모델이 창의성을 회복하도록 `temperature`를 기존 `0.0~0.1`에서 `0.4~0.6` 수준으로 상향 조정합니다.

## 3. 데이터 양에 따른 하이퍼파라미터(Hyperparameters) 튜닝 전략

| 데이터 양 | Epochs (반복 학습) | Batch Size | LR Multiplier (학습률) | 전략 및 주의사항 |
| :--- | :--- | :--- | :--- | :--- |
| **초소형 (50건 내외)** | `4` ~ `5` | `1` | `0.05` ~ `0.1` (낮게) | 여러 번 반복하되 기존 지식을 잃지 않도록 학습률(LR)을 매우 낮게 잡아 천천히 스며들게 합니다. |
| **소형 (100~300건)** | `3` (권장) | `auto` (보통 1~2) | `auto` | 가장 스탠다드한 구간입니다. 3 Epochs를 돌리면서 Validation Loss가 튀지 않고 우하향하는지 관찰합니다. |
| **중형 (500건 이상)** | `1` ~ `2` | `auto` (보통 4 이상) | `auto` | 500건은 포맷 강제화에 충분합니다. Epochs를 3 이상 주면 '과적합(Overfitting)'이 발생하여 모델이 기계처럼 변합니다. |

## 4. 파인튜닝 최고 전문가의 핵심 고려 사항 (Top-Tier Tips)

### 💎 Tip 1. "안다"고 착각하게 만들지 마라 (RAG + FT의 최대 딜레마)
많은 개발자가 파인튜닝 시 "질문-정답"만 넣고 RAG 검색 결과를 같이 넣어주지 않는 실수를 합니다. 
*   **해결책**: 학습 데이터(`messages` 배열) 안에 반드시 가상의 검색 결과(Context)를 함께 넣어주고, *"주어진 Context를 기반으로 대답해라"*라는 훈련을 시켜야 합니다. Context가 주어지지 않은 질문 데이터에는 *"수집된 정보가 없어 답변할 수 없습니다"*라고 답하는 데이터를 필수로 넣어야 실전에서 뇌피셜(할루시네이션)을 방지할 수 있습니다.

### 💎 Tip 2. Router와 Generator는 '별도의 자아'다
현재 시스템은 의도 분류(Router)와 답변 생성(Generator) 두 가지 LLM 노드가 있습니다. 학습 데이터(`.jsonl`) 안에 Router용 데이터(JSON 출력)와 Generator용 데이터(마크다운 출력)를 섞어서 학습시키면 모델이 혼란스러워합니다.
*   **해결책**: 가급적 **Generator(최종 답변 생성) 역할에만 100% 집중하여 하나의 모델을 파인튜닝**하고, 단순 분류 역할인 Router는 튜닝 없이 기존 `gpt-4o-mini`에 JSON-mode만 켜서 사용하는 것이 성능/비용 면에서 훨씬 깔끔한 설계입니다.

### 💎 Tip 3. 띄어쓰기 하나가 모델을 망친다 (Data Consistency)
10,000개의 대충 만든 데이터보다 **100개의 완벽한 데이터**가 무조건 이깁니다. 모델은 아주 미세한 패턴까지 학습합니다.
*   어떤 데이터는 `⚠️ 면책 고지: 본 시스템은...` 이고, 다른 데이터는 `⚠️면책 고지 : 본 시스템은...` 처럼 띄어쓰기나 기호가 다르면 안 됩니다. 100개 데이터의 마크다운 포맷팅과 기호를 100% 완벽하게 통일(Linting)시킨 후 학습을 돌리세요.

### 💎 Tip 4. System Prompt 동기화의 함정
파인튜닝 시 `.jsonl` 데이터셋 안에 넣었던 `{"role": "system", "content": "..."}` 문구는 실제 프로덕션 코드(`naming_graph.py`)의 System Prompt와 **토씨 하나 안 틀리고 100% 동일**해야 합니다. 다를 경우 모델이 포맷을 잊어버리고 오작동할 확률이 급격히 높아집니다.
